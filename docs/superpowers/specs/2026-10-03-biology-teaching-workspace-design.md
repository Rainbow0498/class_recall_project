# 生物教学工作台：第一版设计

日期：2026-10-03

部署信息更新：2026-10-04

状态：用户于 2026-10-04 确认整体设计。第一版已实现并完成本地测试，服务器部署尚未执行。

## 1. 使用目标

为一名高中生物老师提供学生管理、教学进度、排课和课后反馈工作台。授课形式为一对一，只有老师本人登录使用。支持电脑和手机浏览器，数据保存在服务器，两端查看同一份数据。

核心流程：查看课程 → 打开学生课程 → 填写本次内容、学生表现、课后作业 → 生成反馈 → 修改 → 保存反馈并更新进度 → 复制给家长。

## 2. 已确认的需求

### 学生档案

- 新增、查看和修改学生。
- 姓名、当前年级、教学进度、平时分、最近考试分、目标分、期望学校。
- 教学进度由教材、章节、主要内容组成，老师手动填写；第一版不内置完整教材目录。
- 平时分支持裸分和赋分；允许只填写其中一项。
- 最近考试成绩从考试记录中取最近一次，显示裸分和赋分。
- 目标分默认使用赋分口径，明确标注。
- 考试记录包含考试日期、裸分和赋分。通常满分为 100 分，第一版不增加独立满分字段。
- 日常移除学生采用停课归档，保留历史反馈和成绩；归档学生可以恢复。
- 彻底删除作为独立操作，明确展示将删除的关联数据并再次确认。

### 排课

- 查看所有学生的本周课表，并切换周次。
- 查看单个学生的课程安排。
- 支持某一天、某个时段的单次新增课程。
- 支持根据学生、起止日期、每周哪些天、上课时段批量生成重复课程。
- 批量操作先预览日期、时段和冲突，再确认保存。
- 时间冲突仅提示，用户确认后仍可添加。
- 重叠课程在同一天的同一时间区域同时显示，保持课程标题可辨认、每节课可独立打开。
- 重复课程调课、取消支持“仅本次”和“本次及之后”。
- 已上完并保存反馈的课程保持原样，批量操作只作用于尚未完成的课程。
- 取消的课程保留取消状态，默认不占用课表时间格，便于恢复和追溯。

### 课后反馈

- 每节课主要填写三个输入：本次上课内容、学生表现、课后作业。
- 支持零散短句和口语笔记，无需先整理成完整反馈。
- 自动带入学生姓名、课程日期和起止时间。
- 教学进度可在课后顺手更新，课程创建时无需填写完整教学目标。
- 下次课目标为可选的内部备课内容，家长反馈不包含这一项。
- 网页直接调用模型生成反馈；生成后允许老师修改，再保存和复制。
- 长期保留每节课的最终反馈。原始生成输入不建立单独的历史笔记库。
- 输入内容在生成失败时保留在当前编辑页面，允许重试或手动写反馈。
- 已有反馈重新生成时，先产生候选文本，再由老师决定替换，避免覆盖已编辑内容。
- 全局模板和生成要求可修改；变更用于以后生成，历史反馈保留原文。

## 3. 页面设计

以下页面组织和操作细节是实现建议，一并提交用户确认。

### 本周课表

作为默认首页。电脑显示周时间网格，手机显示可切换日期的日时间网格。点击空白半小时时段，弹窗选择学生、开始时间与结束时间，再预览确认；重复和批量排课保留完整表单入口。提供上一周、下一周、回到本周、学生筛选和新增课程入口。

课程卡显示学生、年级、起止时间和课程状态。重叠区域显示全部课程，避免后一张卡完全遮挡前一张。点击课程即可进入课程详情和反馈编辑。

### 学生列表与档案

学生列表支持姓名搜索、年级筛选和在读/已归档切换。

学生档案展示基本信息、当前进度、成绩和目标；下方查看该学生课程、历史反馈和考试记录。最近成绩按考试日期排序，同日记录以创建时间区分。

归档学生不再出现在新增排课的默认选择列表中；其已经存在的未来课程仍可查看和单独处理。

### 课程与反馈编辑

页面显示课程基本信息、三个生成输入、可选下次课目标和进度更新区。反馈编辑器支持生成、修改、保存和复制。

提供“保存反馈并更新进度”和“仅保存反馈”，进度变化发生在老师确认保存时，模型生成或新增排课本身不修改学生档案。反馈和进度更新在同一次数据库事务中保存。

历史课程保存的进度不会因学生后续进度变化而改变。修改较早课程时，更新当前进度需要明确选择，避免默认把学生进度回退。

### 设置

管理全局反馈模板和生成要求；提供模型服务配置状态和测试入口。敏感配置通过服务器环境提供，页面显示已配置状态和可修改的非敏感模型选项。

仅设置一个老师账号，由部署配置设置登录信息，提供登录和退出。

## 4. 默认反馈模板与生成约束

```text
{学生姓名}{月}.{日}生物课程情况反馈：
{开始时间}-{结束时间}
一、上课内容
1.……
二、学生情况
1.……
三、课后作业
……
```

模型整理老师提供的内容，保持自然、具体的中文表达：

- 保留事实、数量、学生理解程度和未掌握的问题。
- 不虚构学生表现、考试分数、正确率、课堂事件和作业要求。
- 对口语和重复表达进行适度整理，保留老师语气。
- 输入不充分时保留其概括程度，不用套话补齐；明显缺失的必填输入在页面中提示补充。
- 不把当前进度、下次课目标、成绩和期望学校自动写入反馈。
- 姓名、日期和时间由应用按课程记录组装，模型主要生成三个正文部分。
- 生成用的学生信息仅包含该反馈所需内容，不发送整个学生档案。

可选下次课目标作为当前课程的内部备课字段，允许为空，不要求老师填写后才能生成或保存反馈。

## 5. 数据结构与重要规则

推荐采用以下实体：

- Teacher：单个老师账号和登录凭据的哈希。
- Student：基本信息、当前进度、平时裸分/赋分、赋分目标、期望学校、归档状态。
- ExamRecord：学生、考试日期、裸分、赋分、创建时间。
- CourseSeries：批量排课的关联标识和原始重复规则。
- Lesson：学生、课程日期、起止时间、系列标识、状态、可选内部下次课目标、课后确认的进度快照。
- LessonFeedback：课程对应的最终反馈和更新时间，每节课维护一份可编辑的当前反馈。
- Settings：全局模板、生成要求和非敏感模型配置。

批量排课按指定日期范围生成实际课程记录，而不是无限期重复。系列关联用于确定“本次及之后”的操作范围。修改同一系列中的本次或后续课程，不影响其他系列。所有排课日期和显示统一使用北京时间。

课程状态为待上课、已完成、已取消。保存反馈完成课程；取消课程可恢复；归档不影响已有历史记录。

原始生成输入可以在当前编辑页面临时保留，不作为单独持久记录。已保存反馈是历史查看与后续修改的依据。内部备课目标独立于家长反馈。

批量修改须再次展示操作范围和冲突。已完成课程始终排除在批量调课、取消的范围之外。涉及多节课的变更应整体成功或整体回滚。

## 6. AI 服务建议和配置方式

建议首先接入阿里云百炼北京地域的 `qwen3.7-flash`，采用非思考模式，并限制输出长度。以真实反馈检查事实保留和表达，再决定是否更换模型。服务地址和模型名可配置。

用户申请密钥的步骤：注册阿里云账号，按提示完成实名认证，开通百炼；选择华北2（北京），在 API Key 页面创建并自行保存密钥。

部署环境提供模型服务密钥、服务地址和模型名。生产密钥不写入设计文档、代码、示例配置、版本控制或日志。应用由后端发起调用，浏览器只访问本应用的反馈生成接口。

用户曾在聊天中提供完整密钥。建议用户撤销并重新生成，后续通过服务器配置输入。当前密钥有效性未验证，本文不包含其值。

## 7. 实现与部署建议

推荐一个集成页面和后端的 Web 应用，搭配 SQLite 数据库，打包为 Docker 容器部署到用户的腾讯云 Ubuntu 服务器。具体框架和版本在实施计划中选定并验证。

与其他方案的取舍：拆分前后端并使用独立数据库适合多人并发和复杂扩展，但需要维护更多部署组件；浏览器本地存储适合临时演示，多端共享和后端 AI 调用仍需要服务器。因此第一版选用单应用与服务器数据库。

已知服务器地址为用户提供的 140.143.124.16，正式访问域名为 `www.gyloveyyb.site`。用户说明服务器尚未配置应用运行环境。当前未访问服务器或更改配置，域名是否已解析到该服务器尚未验证。

数据库文件使用持久数据卷，容器更新保留数据。提供数据备份与恢复方法，正式使用前验证备份可以恢复。部署时配置老师登录凭据、模型密钥和应用地址，使用 HTTPS 提供正式访问。

按尚未配置应用运行环境准备部署材料：在 Ubuntu 上配置 Docker 和 Compose，通过容器运行应用和 HTTPS 反向代理，应用所需运行时随镜像提供。用户无需提前单独安装应用语言运行时或数据库服务。

部署按以下顺序执行：

1. 通过用户提供的 SSH 连接方式读取 Ubuntu 版本、可用资源、现有服务、端口和 Docker 状态，再确定初始化步骤。
2. 核对 `www.gyloveyyb.site` 的 DNS 解析是否指向 `140.143.124.16`，以及腾讯云安全组和服务器防火墙是否允许正式访问所需的 80、443 端口。域名可访问及相关启用条件以实际检查结果为准。
3. 初始化缺少的部署组件，创建应用目录、持久数据卷和服务器私有配置，填入老师登录凭据与模型密钥。
4. 启动应用，配置域名反向代理和 HTTPS；证书签发前先核对域名解析和所需端口连通性。
5. 验证正式域名的登录、排课、反馈生成、容器更新后的数据保留，以及备份恢复流程。

服务器登录信息在实际部署时再提供，不阻塞本地开发。开发与打包不会自动更改这台服务器；没有服务器连接方式时，只交付经过验证的部署材料，不声称已经上线。

## 8. 第一版验收

1. 电脑和手机可登录；未登录不能访问学生、课表、反馈或模型调用接口。
2. 新增和修改学生；归档后历史数据保留，恢复后重新进入在读列表。
3. 新增单次课程，按日期范围批量排课，并查看所有学生和单个学生的课表。
4. 对重叠课程显示提醒；确认后两节课都出现在同一时段且可独立打开。
5. 重复课程可只调整本次，也可调整本次及之后；已完成课程保留原样。
6. 输入零散课堂记录后生成三段式反馈；修改、保存、重新打开和复制均保持正确内容。
7. 下次课目标可为空；填写后只用于内部查看。
8. 保存反馈时可更新当前进度；只保存反馈、生成失败和新增课程不会意外改变进度。
9. 添加考试裸分和赋分记录，最近分正确更新，赋分目标标识清楚。
10. 修改全局模板和生成要求后，仅新生成结果采用新规则。
11. API 出错时保留页面输入，已有最终反馈保持可查看和修改。
12. 更新部署后数据仍存在；备份恢复后学生、课程、反馈和成绩可以正常读取。
